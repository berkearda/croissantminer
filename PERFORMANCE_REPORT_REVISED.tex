\begin{abstract}
We evaluate four state-of-the-art large language models (Claude Sonnet 4.5, Gemini 2.5 Pro, Gemini 2.5 Flash, GPT-4o-mini) for automated metadata extraction from academic papers. Claude Sonnet 4.5 achieved 70.6\% overall accuracy with 100\% system reliability, making it the recommended choice for production deployment. This report presents comprehensive field-level scores, error analysis, and exact prompts used.
\end{abstract}

\section*{Executive Summary}

Claude Sonnet 4.5 achieved \textbf{70.6\% overall accuracy} in automated metadata extraction, tied for best performance with Gemini 2.5 Pro. Claude demonstrated \textbf{100\% system reliability} (8/8 successful extractions) across all test datasets.

\begin{center}
\colorbox{successgreen!20}{\parbox{0.9\textwidth}{
\textbf{Key Finding:} Performance varies dramatically across fields—from 100\% (name, URL) to 25\% (live dataset status). RAI fields consistently outperform general fields by 8.7 percentage points (76.0\% vs 67.3\%).
}}
\end{center}

\subsubsection{Key Insights from Error Analysis}

\begin{enumerate}
    \item \textbf{Missing fields dominate weak performance:} publisher (often not extracted), isLiveDataset (rarely extracted), citeAs (sometimes not extracted)

    \item \textbf{Critical failure mode - wrong domain:} The MMMU description error shows Claude can describe a completely wrong dataset (medical instead of multimodal benchmark) - this is a \textit{catastrophic} failure despite 87.5\% overall accuracy on descriptions

    \item \textbf{Common error types by frequency:}
    \begin{itemize}
        \item \textbf{Field not extracted} (40\%): Most common in publisher, isLiveDataset, citeAs
        \item \textbf{Returned "unknown"} (30\%): Primarily in license field despite information being in paper
        \item \textbf{Usage vs methodology confusion} (15\%): Describing how dataset is used instead of how it was collected
        \item \textbf{Over-generalization} (10\%): Missing specific details (author names, use cases, language pairs)
        \item \textbf{Wrong information entirely} (5\%): MMMU medical description error
    \end{itemize}

    \item \textbf{Partial credit is common:} Many fields score 50\% because extraction captures general intent but misses crucial details
\end{enumerate}

\begin{itemize}

\textbf{Example Error:}
\begin{itemize}

\section{Exact Prompts Used}

\subsection{Extraction Prompt - System Message}

\begin{lstlisting}
You are an expert at extracting structured metadata from academic papers about datasets.

**Your task:** Extract metadata according to the Croissant schema from academic papers.

**Extraction Guidelines:**

1. **Accuracy First**: Only extract information explicitly stated or clearly implied in the paper.

2. **No Guessing**: If information is not found, return null or empty values.

3. **Field-Specific Instructions**:
   - **name**: Exact dataset name from paper title/introduction
   - **description**: Synthesize from abstract and introduction (2-3 sentences)
   - **url**: Look in abstract, data availability, footnotes
   - **license**: Check data availability, ethics, appendix sections
   - **creator**: All authors, use "LastName, FirstName" format
   - **datePublished**: Paper publication date (YYYY-MM-DD or YYYY)
   - **dataCollection**: Methodology from "Data Collection" sections
   - **annotatorDemographics**: Extract annotator count, qualifications, demographics
   - **inLanguage**: Languages in dataset (use ISO codes: en, zh, es, etc.)

4. **Format Requirements**:
   - Return ONLY valid JSON
   - No markdown code blocks or extra text
   - Use null for missing fields
   - Dates in ISO 8601 format (YYYY-MM-DD or YYYY)
   - URLs must be full and valid (https://...)

5. **Common Pitfalls to Avoid**:
   - Don't confuse paper's DOI with dataset's URL
   - Don't extract "future work" as current information
   - Don't mix data collection with data annotation
\end{lstlisting}

\subsection{Extraction Prompt - User Message}

\begin{lstlisting}
Extract metadata from the following academic paper according to this schema:

SCHEMA:
{
  "name": "string",
  "description": "string",
  "url": "string",
  "license": "string",
  "creator": "object or string",
  "publisher": "string",
  "datePublished": "string (YYYY-MM-DD or YYYY)",
  "inLanguage": "string (ISO codes)",
  "citeAs": "string",
  "isLiveDataset": "string (Yes/No)",
  "dataCollection": "string",
  "dataCollectionTimeframe": "string",
  "dataAnnotationPlatform": "string",
  "annotatorDemographics": "string",
  "dataUseCases": "string",
  "personalSensitiveInformation": "string"
